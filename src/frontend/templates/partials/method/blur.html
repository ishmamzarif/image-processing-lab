{% if kernel_kind == 'gaussian' %}
                            
K[i,j] = \frac{e^{-(i^2 + j^2)/2\sigma^2}}{\sum_{i',j'} e^{-(i'^2 + j'^2)/2\sigma^2}}, \qquad \sigma = \frac{k}{6} = {{ sigma }}, \quad i, j \in [-r, r]


def gaussian_kernel(size):
    sigma = size / 6.0
    r = size // 2
    d = np.arange(size) - r
    g = np.exp(-(d[:, None] ** 2 + d[None, :] ** 2) / (2.0 * sigma ** 2))
    total = 0.0
    for v in g.flat:
        total += v
    return g / total

        A sampled Gaussian, normalised to sum to 1. With σ = k/6 the kernel spans ±3σ, past which the weights are under 1% of the centre, so the size slider alone sets the strength.

{% elif kernel_kind == 'disk' %}
        
K[i,j] = \frac{[\, i^2 + j^2 \le r^2 \,]}{\big|\{ (i', j') : i'^2 + j'^2 \le r^2 \}\big|}, \qquad r = \lfloor k/2 \rfloor


def disk_kernel(size):
    r = size // 2
    d = np.arange(size) - r
    inside = (d[:, None] ** 2 + d[None, :] ** 2) <= r * r
    return inside / float(np.count_nonzero(inside))

        A flat disc: equal weight inside radius r, zero outside. It is what an out-of-focus lens does to a point of light, which is why this is the lens blur.
{% elif kernel_kind == 'motion' %}
K\big[\, r - \operatorname{round}(t \sin\theta),\ r + \operatorname{round}(t \cos\theta) \,\big] = \frac{1}{n}, \qquad t = -r, \dots, r, \quad \theta = {{ angle }}^\circ
def motion_kernel(size, angle):
    r = size // 2
    theta = angle * np.pi / 180.0
    kernel = np.zeros((size, size), dtype=np.float64)
    for t in range(-r, r + 1):
        x = int(np.floor(r + t * np.cos(theta) + 0.5 + 1e-9))
        y = int(np.floor(r - t * np.sin(theta) + 0.5 + 1e-9))
        kernel[y, x] = 1.0
    return kernel / np.count_nonzero(kernel)
A line of equal weights through the centre, n cells long: what a camera moving in a straight line during the exposure does to every point. Rows run downwards, hence the minus on the sine. {% else %}
K[i,j] = \frac{1}{k^2}
def box_kernel(size):
    return np.ones((size, size), dtype=np.float64) / (size * size)

②
\tilde{K}[i,j] = K[\,k-1-i,\ k-1-j\,]
kernel = kernel[::-1, ::-1]
The flip is what makes this convolution rather than correlation. Box, Gaussian and circular kernels are symmetric through their centre, so for them it changes nothing; a motion line whose points fall exactly half-way between cells is the one case where it actually moves.
③
\begin{aligned} \mathrm{pad}[y,x] &= \mathrm{src}\big[\operatorname{clamp}(y-p,\,0,\,H-1),\ \operatorname{clamp}(x-p,\,0,\,W-1)\big] \\ p &= \lfloor k/2 \rfloor \end{aligned}
p_height, p_width = k_height // 2, k_width // 2
padded = np.pad(channel, ((p_height, p_height), (p_width, p_width)), mode="edge")
Replicating the border keeps the output the same size as the input.
④
\mathrm{out}[y,x] = \sum_{k_y=0}^{k-1} \sum_{k_x=0}^{k-1} \mathrm{pad}[y+k_y,\ x+k_x] \cdot \tilde{K}[k_y,k_x]
for y in range(h):
    for x in range(w):
        total = 0.0
        for ky in range(k_height):
            for kx in range(k_width):
                total += padded[y + ky, x + kx] * kernel[ky, kx]
        out[y, x] = total
One multiply-accumulate per kernel cell, per output pixel, per channel. Cost is O(H·W·k²) — which is why the times climb with k.
