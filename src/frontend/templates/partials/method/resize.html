Equations

①
W' = \lfloor W \cdot s + 0.5 \rfloor, \quad H' = \lfloor H \cdot s + 0.5 \rfloor, \qquad s = {{ scale }}\%
return max(1, int(old_size * scale + 0.5))
The new width and height: the old ones times the scale, rounded to whole pixels. The image keeps its shape because both sides use the same scale.
②
\text{step} = \frac{W}{W'}, \qquad p_0 = \frac{\text{step}}{2}, \quad p_{i+1} = p_i + \text{step}, \qquad \text{old column}_i = \lfloor p_i \rfloor
step = old_size / new_size
position = step * 0.5
positions = []
for i in range(new_size):
    positions.append(int(position))
    position += step
Which old column sits under the middle of each new column. The first middle is half a step in, and each next one is a step further. Shrinking makes the step bigger than 1, so some old columns are skipped; enlarging makes it smaller than 1, so old columns are used more than once. Rows are found the same way.
③
\mathrm{out}[y, x] = \mathrm{in}\big[\text{old row}_y,\ \text{old column}_x\big]
for y in range(height):
    for x in range(width):
        out[y, x] = image[rows[y], columns[x]]
Every new pixel is a straight copy of one old pixel, all three channels at once. Nothing is mixed, so no new colours appear, which is what makes nearest neighbour look blocky when it enlarges.
