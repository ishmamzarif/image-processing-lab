Equations

①
\mathrm{out}_c[y,x] = \mathrm{src}_c[y,x] + d_c, \qquad d_R = {{ red }}, \quad d_G = {{ green }}, \quad d_B = {{ blue }}
for y in range(h):
    for x in range(w):
        out[y, x] = channel[y, x] + offset
The same point operation as Brightness, but added rather than multiplied, and a different amount for each channel. That changes the balance between them, so unlike a shared gain it moves the hue: lifting red alone turns a grey pixel pink. It is how a colour cast is put in or taken out. The same offset on all three would be brightness by addition instead.
②
\mathrm{dst}_c[y,x] = \operatorname{clip}(\mathrm{out}_c[y,x],\ 0,\ 255)
shifted = np.clip(shifted, 0, 255).astype(np.uint8)
{% if clipped %}{{ clipped }}% of the values ran off one end or the other and were pinned there. {% endif %}An offset clips at both ends, and it costs contrast as well: a positive dc maps the channel's 0–255 onto dc–255, so its blacks are lifted off black. Everything is a whole number, so the astype truncates nothing.
③
\mathrm{lut}_c[v] = \operatorname{clip}(v + d_c,\ 0,\ 255), \quad v = 0, \dots, 255, \qquad \mathrm{dst}_c[y,x] = \mathrm{lut}_c\big[\mathrm{src}_c[y,x]\big]
lut = []
for d in offsets:
    lut += [min(max(v + d, 0), 255) for v in range(256)]
img.point(lut)
How the library does it. The output depends on the input value alone, so each channel has only 256 possible answers: work them out once, then every pixel is a lookup. 768 evaluations instead of 3·H·W, and the lookups themselves run in C.
