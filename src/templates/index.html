{% if kernel_kind == 'gaussian' %}
                            
K[i,j] = \frac{e^{-(i^2 + j^2)/2\sigma^2}}{\sum_{i',j'} e^{-(i'^2 + j'^2)/2\sigma^2}}, \qquad \sigma = \frac{k}{6} = {{ sigma }}, \quad i, j \in [-r, r]


def gaussian_kernel(size):
    sigma = size / 6.0
    r = size // 2
    d = np.arange(size) - r
    g = np.exp(-(d[:, None] ** 2 + d[None, :] ** 2) / (2.0 * sigma ** 2))
    total = 0.0
    for v in g.flat:
        total += v
    return g / total

                            A sampled Gaussian, normalised to sum to 1. With σ = k/6 the kernel spans ±3σ, past which the weights are under 1% of the centre, so the size slider alone sets the strength.

{% elif kernel_kind == 'disk' %}
                            
K[i,j] = \frac{[\, i^2 + j^2 \le r^2 \,]}{\big|\{ (i', j') : i'^2 + j'^2 \le r^2 \}\big|}, \qquad r = \lfloor k/2 \rfloor


def disk_kernel(size):
    r = size // 2
    d = np.arange(size) - r
    inside = (d[:, None] ** 2 + d[None, :] ** 2) <= r * r
    return inside / float(np.count_nonzero(inside))

                            A flat disc: equal weight inside radius r, zero outside. It is what an out-of-focus lens does to a point of light, which is why this is the lens blur.
{% elif kernel_kind == 'motion' %}
K\big[\, r - \operatorname{round}(t \sin\theta),\ r + \operatorname{round}(t \cos\theta) \,\big] = \frac{1}{n}, \qquad t = -r, \dots, r, \quad \theta = {{ angle }}^\circ
def motion_kernel(size, angle):
    r = size // 2
    theta = angle * np.pi / 180.0
    kernel = np.zeros((size, size), dtype=np.float64)
    for t in range(-r, r + 1):
        x = int(np.floor(r + t * np.cos(theta) + 0.5 + 1e-9))
        y = int(np.floor(r - t * np.sin(theta) + 0.5 + 1e-9))
        kernel[y, x] = 1.0
    return kernel / np.count_nonzero(kernel)
A line of equal weights through the centre, n cells long: what a camera moving in a straight line during the exposure does to every point. Rows run downwards, hence the minus on the sine.

    return 100.0 * float(np.mean(diff)) / 255.0

A point operation: each output pixel depends on its own input pixel and nothing else, so there is no neighbourhood, no padding and no kernel. One multiply per value, O(H·W), against the blur's O(H·W·k²). Every channel is scaled by the same g, so the ratios between them, and with them the hue, hold until a channel clips.
